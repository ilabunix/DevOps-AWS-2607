We have identified a collision in our centralized FRFS Grafana Org. Multiple application repositories such as Compass and Training Center independently provision grafana_notification_policy. Since that Terraform resource represents the entire Grafana notification policy tree, whichever application applies last overwrites the other application’s notification policies.

We cannot introduce a centralized owner/repository for the notification policy tree. Each application must continue to own and deploy its Grafana configuration independently.

Please review the current Terraform implementation and determine how to migrate notification routing away from grafana_notification_policy and instead use the notification_settings block directly inside each application’s existing grafana_rule_group.rule blocks.

Our environment:

* Grafana Enterprise v12.4.5+security-01
* Terraform Grafana provider v3.21.0
* Applications have independent GitLab repositories/pipelines
* Applications already provision their own grafana_contact_point resources
* Do NOT introduce centralized notification-policy ownership
* Do NOT upgrade the Grafana provider unless there is a separate technical requirement

Target design:

* Compass alert rules directly route to Compass contact points such as compass-dev, compass-test, compass-uat, etc.
* Training Center alert rules directly route to its own corresponding contact points.
* Each application remains fully independent.
* Remove/stop applying grafana_notification_policy from the individual application repositories after direct routing is successfully validated.
* The Grafana Default Policy can remain only as a fallback for alerts without explicit notification settings.

First inspect the existing grafana_rule_group, grafana_contact_point, and grafana_notification_policy modules. Do not modify anything yet. Show:

1. Whether notification_settings is supported by our current implementation/provider.
2. Whether the Grafana alertingSimplifiedRouting feature flag needs to be verified/enabled.
3. Exactly which Terraform files/modules need changes.
4. A minimal TEST-environment change for one Compass alert before applying this pattern to every rule.
5. What happens to the existing labels, grouping settings, group wait, group interval, and repeat interval.
6. The Terraform plan we should expect and any risk of destroying/recreating existing alert rules.
7. How to safely remove grafana_notification_policy from Terraform state/config after the new routing has been validated without accidentally deleting contact points or alert rules.

Do not perform changes until the proposed diff is reviewed.
