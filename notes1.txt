==================================================
OBJECTIVE
==================================================

We currently receive Grafana's default email notifications.

They contain useful information, but also a lot of noise such as:
- Grouped by
- __alert_rule_uid__
- __grafana_autogenerated__
- internal receiver/routing labels
- route hashes
- raw A=1 B=1 C=1 values
- all labels and annotations whether operationally useful or not

We want to replace the default subject/message content with one reusable FRFS CloudOps notification template.

The template should work across 20+ applications and support:

1. Application alerts
2. CloudWatch log alerts
3. Job/data-processing alerts
4. AWS infrastructure alerts:
   - ECS
   - RDS / Aurora
   - ALB
   - Lambda
   - API Gateway
   - DynamoDB
   - S3
   - other CloudWatch metric-based alerts

The implementation must be:
- reusable
- Terraform-managed
- application agnostic
- backward compatible
- minimal
- safe for the centralized Grafana org
- suitable for DEV/TEST/UAT/PROD
- easy to maintain

IMPLEMENTATION APPROACH
==================================================

Use the Grafana Terraform resource:

grafana_message_template

Prefer one reusable template group named something similar to:

FRFS CloudOps Email

Inside it, define reusable templates such as:

frfs.cloudops.subject
frfs.cloudops.message


Conceptual Terraform structure:

resource "grafana_message_template" "frfs_cloudops_email" {
  name = "FRFS CloudOps Email"

  template = <<EOT

{{ define "frfs.cloudops.subject" -}}

...dynamic subject logic...

{{- end }}


{{ define "frfs.cloudops.message" }}

...dynamic notification body...

{{ end }}

EOT
}


Then modify the existing email contact point so it references:

subject = "{{ template \"frfs.cloudops.subject\" . }}"
message = "{{ template \"frfs.cloudops.message\" . }}"


Do not create a new contact point unless necessary.

Prefer updating the existing email contact point that currently sends the default Grafana notification.
